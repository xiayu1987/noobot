# 存储架构核查：2026-11-23

本次核查以当前工作树为准。工作树已有大量存储重构改动；下述结论不代表已部署版本、生产数据检查、掉电验收或全架构完成。

## 本次修复

连接器注册表仍由 Session 持久化端口管理，Connector 协议负责记录与迁移契约。没有增加第二份注册表、在线旧格式兼容或损坏数据过滤入口。

| 已证实的问题                                                       | 原因                                                         | 修复与验证                                                                                                                                                  |
| ------------------------------------------------------------------ | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 非数组记录集被置空，字段缺失的记录被丢弃，后续写入可能覆盖原始条目 | 仓储内 `Array.isArray(...) ? ... : []` 与 `.filter(Boolean)` | 移除两条旁路；协议逐条验证。读取、创建、更新、删除均拒绝损坏源，测试逐字节核对文件未变化                                                                    |
| 同一 ID 可重复创建，记录归属没有与读取用户核对                     | 仓储只检查名称冲突                                           | 协议统一验证 ID、名称唯一性及 owner；重复创建失败后，下一次有效写入仍可成功                                                                                 |
| 显式旧格式迁移可漏项、改身份，旧参数损坏可变为空对象               | 迁移只检查目标记录是否合法，未与源逐条核对                   | 协议要求源与目标身份字段完全保全，参数必须为对象；迁移漏项、改 ID、改名称或改 owner 均拒绝且保留源                                                          |
| 不同仓储实例或进程读改写同一文件可相互覆盖                         | `userLocks` 仅存在于单个实例内                               | 移除实例内 Promise 锁，复用描述符锁；三独立写进程并发新增后，所有已确认条目均存在                                                                           |
| 原子改名没有文件及目录同步边界                                     | 注册表使用普通原子写工具，写后再 chmod                       | 复用持久发布工具：暂存从创建起为 0600，写入并同步正文、关闭、改名、同步父目录；同步失败传播错误。独立进程在改名前后退出，下一次写入可以继续且不丢已发布事实 |

实现与回归：

- [注册表协议](../connector-protocol/src/instance-registry.js)：格式版本、记录身份、归属、唯一性与迁移保全。
- [仓储](../agent/src/session/repositories/file-system-connector-instance-repository.js)：位置、锁与持久发布；不再重复维护唯一性规则。
- [持久发布工具](../agent/src/shared/storage/durable-file.js)：增加创建权限参数，保留已有发布与错误清理流程。
- [完整性回归](../agent/__tests__/integrations/connector-registry-integrity.test.js)、[并发及中断回归](../agent/__tests__/integrations/connector-registry-publication.test.js)。

有效的 v3 文件格式不变；非数组记录集、缺少身份字段、重复身份、错误归属、字符串版本等输入现在显式拒绝。首次不存在的注册表仍表示尚未创建，只有 ENOENT 允许此语义。旧 v2 只通过显式迁移入口解释。版本未知或已是 v3 但内容损坏，不能当作没有迁移任务。

注册表锁实现更新需要所有写入进程统一使用本实现；旧实现不持锁，不能与新实现并发写入。暂存文件不授权读取；进程中断遗留的固定暂存由下一次持锁发布回收。改名之后、目录同步之前失败，调用方必须读取当前注册表核对结果，不能将返回错误解释为一定未发布。测试证明的是进程退出恢复与注入错误处理，未证明掉电后的设备持久性。

## 已核对但仍未完成的架构目标

### 执行查询的有界定位

[ExecutionReadService](../agent/src/session/services/execution-read-service.js) 仍枚举参与查询的会话；[分区执行来源](../agent/src/session/partition-storage/partition-session-source.js) 仍读取整个 lifecycle 键集。现有错误语义会将任一不可读来源报告为查询不完整，没有把未知当成不存在，但工作量仍随无关会话和历史增长。

完成条件：先在协议中定义执行 ID、直接父执行、根执行到已发布会话事实的定位声明及退役；覆盖创建、替换、删除、迁移和中断恢复。索引只保存定位，不维护第二份执行状态。缺失或滞后的定位须显式报告未就绪，不能静默全扫。续页需要固定读取视图、预算与释放责任，再以递增无关会话的冷读验证打开数、候选数和字节界限。

### 聊天详情分页消费

[详情请求](../client/noobot-chat/src/modules/session/model/list/sessionDetailRequests.js) 仍调用完整详情 API，并使用完整分支文档协议。已有分区分页端口不等于浏览器首屏已切换。

完成条件：Session 协议先定义首屏轮次如何有界定位跨会话的已提交附件引用，声明来源视图及失效条件，区分完整且为空、归属冲突、来源不可读、定位未完成。随后统一切换选会话、重连及详情刷新，验证切会话释放、正文版本冲突、子轮附件归属；不允许拉齐所有分页重建完整详情。

### 持续空间回收与组合准入

[容量协议](../session-protocol/src/partition-journal-capacity.js) 提供单 journal 配额及发布预留。[Outbox 压缩](../agent/src/session/partition-storage/partition-outbox.js) 处理逻辑投递状态，不代表旧物理分区已安全回收。[架构文档](session-storage-architecture.md) 仍将生产维护器与工作区级组合准入列为未验收目标。

完成条件：由同一发布协议完成有界候选选择、存活事实搬迁、持久发布、引用释放后删除，并核对读者、有效回执、投递及迁移保留。工作区及磁盘准入必须覆盖多个 journal、维护临时空间和必要恢复余量。单 journal 满时拒绝写入不能证明长期空间闭环。

### 删除与恢复的剩余验收

服务层已通过目录、会话树、插件、附件、短期记忆阶段的进程中断续跑回归，覆盖活跃跨进程读者保护与迟到写入拒绝。尚需逐类核对其他写入者、掉电场景、锁吞吐、删除记录保留与容量边界。不得把进程退出测试提升为掉电保证。
