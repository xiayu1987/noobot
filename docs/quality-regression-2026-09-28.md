本次根因修复：

- 辅助模型执行器原本由主系统识别 harness/workflow 业务名称来决定展示，并在无工具、工具循环、轮数上限收尾中重复调用模型。现在由插件通过 `@noobot/plugin-protocol` 声明 `activity`，主系统统一调用 `ModelPort`、发布规范消息事件。删除按插件名称推断展示类型和不可达的旧事件发布分支。
- 工具循环为后续轮次构造独立消息数组，避免修改已经交给模型的请求快照。回归断言验证第一轮请求内容不被第二轮结果改写。
- 消息角色和内容解析复用 Context 协议的 codec，辅助模型执行器不再维护独立的 SDK 字段解析分支。
- 可视化模型访问测试的请求体大小、超时收敛到共享数量与时间阈值。
- 恢复最终主消息测试遗漏的实际调用与断言，验证唯一的权威终态内容事件。
- 启动器模型库初始化测试改用当前目录中的 `gpt-6-sol`，修复使用已删除型号导致的失效断言。
- 清理未使用导入、重复导入和不符合仓库规则的源码注释；保留文件链接解码行为。
- 格式检查纳入尚未被 Git 跟踪的新文件，消除本地新增源码漏检。

插件展示协议：

```js
import { defineCapabilityActivity } from "@noobot/plugin-protocol";

await capabilityModelInvoker({
  activity: defineCapabilityActivity("custom_review"),
  messages,
  ctx,
});
```

`activity` 省略或为 `null` 表示不请求活动展示；显式对象只允许非空字符串 `activityKind`。非法字段直接拒绝。harness 分析和 workflow 语义规划分别在插件内部声明自己的展示类型，主系统不识别这些业务名称。流式偏好通过既有 `ModelPort` 传递；收到流式片段时逐片发布，整包结果只发布一次，已经发布片段的结果不再重复整包发布。
