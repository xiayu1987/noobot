# 工具调用名称绑定

工具的内部身份与模型调用名称分离。配置字段使用 `bindingName`：它是模型声明和调用所使用的名称，不是界面标题。内部工具对象的 `name` 继续承担稳定身份，授权、策略、执行和规范历史记录均使用该身份。

## 配置

用户可在前端“用户配置 → 工具 → 工具调用名称”中搜索选择内置工具，添加后直接编辑调用名称并保存。界面显示继承名称，“恢复继承”删除该工具的用户覆盖；有全局绑定时恢复全局名称，否则使用原名。工具目录来自 Agent 公开的内置身份声明，前端不维护工具清单；目录用于名称配置，不代表当前场景已装配或授权。

配置声明接口提供 `toolBindings: { toolIds, bindings }`，其中 `bindings` 是全局名称配置。前端实时提示和保存校验、服务端用户根目录 `config.json` 写入校验共用配置协议 `resolveToolBindingSettings`，通过模型绑定协议检查格式以及与继承名称、未改名内置工具和已有扩展配置的冲突。非法写入返回 400，原文件保持不变。已有插件和 MCP 绑定保留并可编辑；新增选择列表目前只提供内置工具。

在全局或用户配置中设置：

```json
{
  "tools": {
    "bindings": {
      "read_file": { "bindingName": "nb_read_document" },
      "execute_script": { "bindingName": "nb_run_command" },
      "help": { "bindingName": "nb_help" }
    }
  }
}
```

用户配置通过既有配置合并协议覆盖对应条目，未覆盖的全局条目保留。未声明绑定的工具以稳定身份作为调用名称。名称须为 1–64 个 ASCII 字母、数字、下划线或连字符；非法配置和重名直接报错。显式空值不会回退到默认名称。

全局配置和用户配置在过滤、修复或合并前分别校验原始绑定声明，合并后校验跨层名称冲突。绑定字典中的键是工具身份，不能按配置结构字段的 snake_case/camelCase 规则改写。配置字典统一写入自有数据属性，`__proto__`、`constructor` 等身份在归一化、用户投影、修复与合并后保持原样，不读写对象原型。

配置键必须是稳定工具身份。插件工具沿用注册协议提供的身份。MCP 工具由 `createNamespacedToolId("mcp", serverName, remoteToolName)` 生成身份，包含服务器与远端工具来源，避免字符清洗、截断和枚举顺序造成冲突；调用远端 MCP 时仍传原始远端名称。

## 请求与执行

`@noobot/model-protocol` 提供名称校验、不可变双向绑定、消息投影、指定工具选择投影与响应还原。Agent 模型宿主在每次请求开始时生成绑定，将工具声明、历史调用和 `tool_choice` 投影为调用名称，再交给运营商适配器。模型返回结果在进入执行流程前还原为内部身份。

在途配置修改不会改变已有请求的响应解析和执行文案。规范调用通过协议 Symbol 携带请求绑定，执行器的异步绑定作用域覆盖前处理、工具调用、结果物化、错误钩子、溢出处理和完成钩子；帮助查询、手册和工具列表使用该请求的名称与活动工具集合。作用域随调用结束，不落盘，也不在并发请求间共享。独立工具调用入口按当前有效配置建立绑定；模型执行入口在参数修复和事件发送前要求原请求绑定，缺失时明确拒绝。运行时文案不得自行读取配置重建绑定。

模型宿主通过响应协议的 `toolNameBindings` 提供冻结的请求名称视图，主流程输出投影保留该字段。Harness 转发模型内容时必须使用来源响应的视图，不读取宿主 runtime 或合并实时配置；纯本地生成的通知显式使用空视图。辅助模型未调用或任务已终止时返回未调用状态，调用方停止结果处理，不生成报告或转发内容。

绑定协议以 `tools` 声明作为活动集合和手册能力的唯一来源，从中派生只读身份列表；不再接收独立的 `toolIds` 输入。重复身份、无效声明和未知选项在建立绑定时明确拒绝。工具声明和指定工具选择只接受活动身份，历史名称解析与活动调用校验分离。模型返回未声明名称、旧名称或仅存在于历史中的工具名称时，明确报错，不猜测、不模糊匹配，也不执行。

执行器与内置工具入口复用协议 `assertToolExecution`，要求稳定调用身份属于绑定的活动集合，且与实际工具身份一致；校验先于参数修复、事件、钩子和工具副作用。独立调用同样执行该校验，已有绑定作用域不免除检查。

内置与 MCP 工具共用 `boundTool` 执行构建入口；本地化手册和模板标记只由内置工具声明。MCP 子任务执行使用每个调用携带的原请求绑定，覆盖外层任务作用域，结束后恢复；直接调用 MCP 工具必须显式提供绑定作用域。

历史存储继续使用内部身份，重放时按照本次请求绑定投影。历史中已退役工具可以保留展示名称，但不会获得执行权限；其名称与当前工具冲突时在发送前报错。此次功能没有改写存量会话或生产配置。

包含顶层或嵌套签名的客户端调用以 `signed_tool_call` 保存规范 `toolId` 和不改写的 `providerCall` 原文，执行用的规范调用仍使用内部身份。存储恢复后，重放先核对当前绑定与签名原文中的名称；一致时发送原文，需要改名时明确报错，要求建立新的模型上下文。服务端内建调用不参与客户端名称映射。

## 帮助与文案

机器生成说明使用 `{{tool:read_file}}` 这样的显式引用。模型侧工具说明、系统提示、场景说明及帮助手册按配置渲染；普通用户文本、工具参数和返回正文不做全文替换。

工具创建通过 `tToolTemplate`、`tToolDescription` 和 `tToolParamDescription` 获取未绑定说明。系统模板在组装时编译为文本块与 `tool_name_reference` 块；长期记忆、目录、技能、服务等业务数据保持普通文本。场景工具列表使用引用块，其他数据字段不编译。模型宿主只投影显式引用，不按 system/developer 角色扫描整条正文；结构化边界经过上下文序列化恢复后继续保留。

内置工具通过统一 `structuredTool` 构建入口设置协议标记 `TOOL_DEFINITION_TEMPLATE`，声明导出保留该标记。strict 与非 strict 模式都先导出对应 JSON schema，再按本次绑定投影明确标记的说明字段；schema 属性名、默认值、枚举、常量和示例作为数据原样保留。未标记的 MCP 和插件声明只投影调用名称，描述及 schema 文本均为不透明数据，不解析宿主模板语法。标记在发送前删除。

运行时工具提示通过 `tTool` 在调用绑定作用域内渲染。带参数的翻译函数只对静态模板片段调用 `transformText`，参数作为不透明数据插入，禁止对插值后的结果再次替换。帮助按调用绑定渲染手册；说明和参数查询不再重复合并配置或投影整份条目。

工具通过模型协议的 `TOOL_MANUAL_PROVIDER` 声明同步手册提供器，绑定在请求开始时捕获提供器。`getToolManual(toolId)` 仅接受活动身份，返回 `{ status: "available", manual }` 或 `{ status: "unsupported" }`；提供器必须返回非空普通对象，错误直接暴露。内置构建入口注册本地化提供器，目录仅读取自有条目。MCP 和插件未声明提供器即表示不支持手册，帮助返回 `manual: null, manualStatus: "unsupported"`；外部手册正文作为数据保留，不解析宿主模板语法。

独立调用的 `invoke` 与执行器共用绑定创建入口，按调用上下文和工具策略筛选完整活动声明。内置工具构建入口保留其上下文，执行器显式提供的调用上下文优先。无原绑定且无上下文时明确拒绝，不从当前工具推断单工具集合；需要单工具执行时由调用方显式提供单工具上下文。执行配置中不再重复传递无人消费的名称绑定。

规范调用、内容块和 Responses 历史使用同一调用位置协议，覆盖 `custom_tool_call`；服务端内建调用不参与客户端名称映射。历史身份采集复用同一位置定义，只读遍历，不复制历史消息。

工具结果按工具消息角色识别，不要求消息携带可选的 `name`。模型宿主通过事件协议解码结果，以同一次请求绑定投影顶层 `toolName`；消息带有 `name` 时，两者的内部身份必须一致。结果不声明 `toolName` 时保留原结构，嵌套业务字段、文件内容和错误正文不做名称替换。非法 JSON、身份冲突或未绑定身份在请求发送前报错。存储及执行事件继续保留内部身份，历史重放重新投影，不改写已有记录。

改名后通过 `nb_help({ command: '--tools --name nb_read_document' })` 查询手册。帮助列表、能力查询与隔离分类展示调用名称；命令索引和错误提示的示例统一来自工具手册。

帮助只根据绑定提供的活动集合回答可用性。未命中的名称统一返回当前不可用及活动名称列表，不从配置或内部常量推断注册状态。

## 验证入口

- `npm run -w model-protocol test`：名称校验、重名、历史投影、指定工具选择、响应还原、签名约束、MCP 身份稳定性。
- `npm run -w agent-config-protocol test`：配置修复、用户覆盖、跨配置层重名。
- `npm run -w agent test`：本地 HTTP 请求报文、strict 两种模式、历史重放、在途配置修改、旧名拒绝，以及帮助入口改名。
- `npm run check:quality`：仓库质量门禁。

本地 HTTP 测试验证实际请求和响应链路；具体运营商的保留名称限制仍需在相应运营商环境验证。
